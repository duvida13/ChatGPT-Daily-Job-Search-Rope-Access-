# Mandatory research workflow

## Start and resume

1. Use the current Europe/Amsterdam date.
2. Fetch this workflow, [search profile](search-profile.md), [current index](../data/job-index.md), today's source sections in [sources](sources.md), and any same-date files under `research/` and `daily/`.
3. Resume a same-date run from its last completed country checkpoint. Do not restart completed countries or duplicate a dated page.
4. Fetch archived detail only when a specific ambiguity cannot be resolved from the compact context.

## Country rotation

Cover all seven preferred countries every day:

- Netherlands
- Switzerland
- Belgium
- Luxembourg
- Norway
- Denmark
- Sweden

Add the weekday rotation:

| Day | Additional scope |
|---|---|
| Monday | United Kingdom and Ireland |
| Tuesday | Germany and Austria |
| Wednesday | France and Italy |
| Thursday | Portugal and Spain |
| Friday | Poland and Romania |
| Saturday | United Kingdom, Germany and promising offshore leads |
| Sunday | Priority revalidation plus deeper company and agency discovery |

Follow a genuine lead into another European country when useful; do not replace the seven-country baseline.

## Mandatory order for every country

1. Run a separate plain-English `rope access jobs <country>` search.
2. Run a separate plain-English `IRATA jobs <country>` search.
3. Search verified local terms and geography.
4. Check known productive employers, specialist/local agencies and portals.
5. Check industrial, rigging, scaffolding, mechanical, shutdown and offshore variants.
6. Check hidden wind/blade/LPS/composite descriptions where supported.
7. Open the actual advert and verify title, employer, locality, scope, requirements, date/status and application route.

Translations never replace the two English baselines. A blocked, fuzzy or login-walled source is a limitation, not an empty market. If a primary portal blocks, use only a legitimate mirror actually observed and retain both identities.

## Verification and deduplication

- Compare canonical URL and job ID.
- Also compare employer, role, actual locality, work scope and campaign.
- Employer + title + country alone is insufficient.
- Treat translations, mirrors and reposts of one campaign as one job.
- Separate live adverts, stale/expired posts, generic pools and uncertain hiring.
- Compare against the complete current index and any pending same-date delta.
- Historical records are not all live offers.
- Never fabricate findings, requirements, dates, counts or coverage.

## Efficient source cadence

- Check known productive sources every daily run for the countries covered.
- Rotate deeper company/agency discovery across the week; perform the broadest source discovery on Sunday.
- Revalidate live/unclear indexed jobs on a documented cadence instead of reopening every historical record daily.
- Prefer one fetch of unchanged context and one readback of each changed publication.

## Checkpoints and output

After each completed country, update the same public `research/YYYY-MM-DD.md` with:

- exact queries;
- sources/adverts inspected;
- verified, duplicate, expired, unclear and blocked outcomes;
- provisional stable-ID delta;
- remaining countries;
- measured metrics, or `unknown` where unavailable.

On completion:

1. Update `data/job-index.md` with stable IDs for verified new campaigns and any evidenced status changes.
2. Write or merge one compact `daily/YYYY-MM-DD.md`, grouped by country and ordered strong, adjacent, stretch.
3. Update `daily/README.md` and `research/README.md` only when the manifest changes.
4. Read back changed files once and record commit/blob receipts in the run.
5. Do not publish to Notion. Local Obsidian synchronization is handled separately.

A completed zero-new run gets an honest coverage report. A failed or incomplete search is never reported as zero-new.

## Safety and privacy

No name, contact details, résumé materials, private history, private application data or internal archive links belong in this public repository. Do not outreach, apply, purchase, change permissions or use another repository.
